# Turing Nebula v2

**Turing Core v0.1 / Milestone 2C**. The workbench navigation and preference refinements below are approved. Remaining v2 proposals retain their separate acceptance criteria.

Nebula v2 puts file work at the center of the IDE. A compact command bar makes actions discoverable, the Explorer keeps the project in view, and the editor has the clearest surface on screen. A 2 px violet edge identifies the active destination. Cyan is reserved for live editor information and useful action cues. This distinction gives the workbench character and makes it easier to scan during long sessions.

- **UI family** `system-ui, -apple-system, "Segoe UI", sans-serif`. Interface body **13/20 px**, controls and labels **12/16 px**, metadata **11/16 px**, welcome headline **28/34 px**, weights **400 / 550 / 650**. Use sentence case.
- **Mono family** `ui-monospace, "SFMono-Regular", Consolas, "Liberation Mono", monospace`. Editor **14/22 px**, gutter and numeric telemetry **12/16 px**, tabular numbers where values update. Keep ligatures off by default. Preserve Monaco’s syntax distinction with foreground `#EFF2F8`, comments `#A1AEC4`, keywords `#C9B4FF`, strings `#A9DDB6`, and numbers `#F2CA83`.
- **Spacing** `4, 8, 12, 16, 20, 24, 32, 48` px. Workbench rails and panel headers align on a 12 px inset. Corners are **4 px** for buttons, **6 px** for fields, **10 px** for floating surfaces, and **0 px** for docked pane edges. Icon glyphs are **16 px** in a **28 px** minimum hit target.
- **States** Rest uses the surface and text tokens. Hover uses `surface-hover`. Pressed uses `surface-selected`. Selection also uses an edge plus weight **650** and semantic state. Keyboard focus gets a 2 px inset ring on dense rows and a 2 px offset ring on isolated controls. Disabled actions retain readable labels and expose a reason where availability is unclear. A dirty tab uses a dot plus an accessible unsaved label. Errors and conflicts use an icon and text as well as color.
- **Motion** **100 ms** color transitions and **140 ms** dialog opacity transition, ease-out. Resize feedback tracks the pointer directly. Reduced motion makes the transitions immediate.

**Layout rules.** Use 6 px splitters with a 1 px visible divider between docked regions. Drag to resize, use direction-correct arrows for 8 px and Shift+arrow for 32 px, Home/End for bounds, and double-click to restore the region’s default. Commit preferences on release or keyboard step. Escape during drag restores the starting size. When resizing the window, shrink side panes toward their minima before the editor. Use docked side panes at **920 px** and above. Below **920 px**, show only one side pane at a time as a **min(272 px, viewport minus 72 px)** nonmodal overlay, anchored after the rail for Explorer or at the right for AI. Closed overlays consume no space and remember the desktop widths. Below **640 px** in browser preview, keep the same overlay behavior and allow the editor to fill remaining width. Preserve existing saved layouts on upgrade. For new profiles, Explorer starts open and the dock and AI panel start closed.

This refinement retains the existing compact stacked layout at **615 px** and below. The sidebar, editor with dock, and AI panel share the second column, and the rail stays on the left. Open panels keep their own visibility, and the editor expands into spare vertical space. The overlay behavior above remains a separate v2 proposal.

**Search and Source Control.** Use the left sidebar's existing region and header. Milestone 3A adds a labeled query field, match options, and grouped results for an authorized workspace. Show distinct idle, pending, no-match, cancellation, and recoverable error states. The browser preview explains that search requires the desktop app. Source Control shows its unavailable state. Run & Debug stays visible, focusable for discovery, and inoperable with an unavailable tooltip.

**Settings.** Open a keyboard-accessible dialog from the rail or the command palette. Escape or Close returns focus to the opener. Auto Save shares the File menu preference and is disabled in the browser preview. Layout settings mirror the bottom-panel and AI visibility controls and offer a reset for saved pane dimensions. Persist approved values locally. Nebula remains the sole appearance, so there is no theme picker.

## Welcome and state design

The welcome surface appears whenever no editor tab is open. It is a **maximum 420 px** action block, vertically centered with a **24 px** minimum inset and left aligned. Use a **40 px** orbital mark above **“Open your workspace”** and a single line, **“Open a folder or start with a single file.”** Three stacked **36 px** rows with **8 px** gaps present **Open Folder**, **Open File**, and **New File**. Give Open Folder the violet emphasis. The footer offers the command-palette shortcut. Browser preview shows **“Try an untitled document”** with New File as the enabled primary action and one sentence explaining desktop-only filesystem access.

| State                         | Presentation and exit                                                                                                                                                                   |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Folder loading                | Inline icon and “Loading folder…” beside the affected branch. Keep the visible ancestor context.                                                                                        |
| Empty folder                  | “This folder is empty.” Keep the workspace actions available.                                                                                                                           |
| Folder read error             | Show the existing safe error and a Reload Folder action. Preserve access to the parent and File menu.                                                                                   |
| Editor loading                | Keep the tab bar and breadcrumb area stable. Announce “Loading editor…” once.                                                                                                           |
| Save failure or disk conflict | One inline strip below breadcrumbs with real status. Preserve the draft. Use Reload from Disk and the existing Save As action. Destructive confirmation stays in the existing workflow. |
| Unavailable feature           | Explain the limit in one line. Show no simulated output, diagnostic count, Git branch, or AI response.                                                                                  |

## Interaction and component architecture

- **Command palette.** Cmd/Ctrl+Shift+P or the launcher opens a **560 px** maximum dialog with a **44 px** search row, **32 px** results, and **28 px** shortcut footer. Search available commands by label and keyword. Use Up/Down to navigate, Enter to run, and Escape to dismiss. Restore focus to the originating control on dismissal. A command that opens a document or dialog hands focus to that destination.
- **Menus.** File and the palette share command descriptors for Open Folder, Open File, New File, Save, Save As, Auto Save, and Close File. Retain established save shortcuts and display only implemented bindings. Outside click, Escape, action completion, and window blur dismiss File. Use real context actions for existing files, folders, and tabs that also work by keyboard.
- **Keyboard.** Explorer uses arrows to move within visible rows, Right/Left to expand, descend, or return, and Enter to open. Editor tabs and dock tabs use roving tab stops and Left/Right, Home, and End. Keep visible focus when switching tabs by keyboard. Each icon-only action has an accessible name and a tooltip on hover or keyboard focus.
- **React boundaries.** Compose `Workbench` from header, shared command descriptors, activity rail, Explorer, editor region, dock, AI panel, and status bar. Keep the existing editor and Explorer services as the behavior owners. Lazy-load Monaco and workers, keep editor models separate from view preferences, and subscribe to narrow Zustand slices. Keep drag previews transient. Persist only versioned and validated dimensions and visibility, with no document content or native handles.

## Acceptance criteria for implementation

1. **Visual.** Review native and browser shots at **1440×900**, **1024×768**, and **680×520**, plus browser preview at **390×844**. Include welcome, active editor, palette, File menu, loading, and conflict states. Check 1 px divider alignment and explicit active states. At compact sizes the overlay leaves the rail reachable, essential actions stay visible, and only the panes or editor scroll.
2. **Accessibility.** Measure enabled normal text against its actual surface at **4.5:1** or better. Measure essential controls and focus indicators at **3:1** or better. Verify keyboard-only Explorer, tabs, menu, palette, and splitters, with focus restored and free of obscuring overlays. Check reduced motion, 200% zoom, and screen-reader announcements of status changes. [WCAG 2.2](https://www.w3.org/TR/wcag22/)
3. **Layout.** Verify the rail order, unavailable Run & Debug and native-only Search states, independent AI and sidebar visibility, Settings focus restoration, and dock selection across close and reopen. Test pointer and keyboard resizing, bounds, cancellation, and persistence after reload. Collapse or resize panes without losing tab or caret state. A new profile gets the proposed defaults and an existing profile retains its saved preferences.
4. **File workflows.** Re-run coverage for workspace and standalone open, New File, Save, Save As, Auto Save, tabs, dirty state, confirmation, external change, and browser-preview restrictions. Verify no native authorization, IPC, CSP, or secure-save behavior changes.
5. **Quality.** Pass lint, formatting, typecheck, frontend and Rust regression suites, the production frontend build, and the locked native build. Check native launch and keyboard interactions on available macOS, Windows, and Linux hosts. Record each platform or interaction that could not be verified.
