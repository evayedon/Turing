# Turing v0.2 acceptance: Turing Intelligence

v0.2 is accepted when the release gate in
[SRS §8](../Turing_SRS_v1.0.md) holds on native builds: at least one local and
one cloud model, indexing, and traceable context. Run this checklist on macOS,
Windows, and Linux with the same commit. Record the commit, OS version, and a
pass, fail, or blocked result for each section. For a failure, note the step,
the expected and actual result, and a screenshot. CI builds and unit tests are
separate evidence and do not replace this run.

## Before you start

1. Run `pnpm install`, then `pnpm dev:desktop` from the repository root.
2. Create a test folder with two files:
   - `limits.rs`: `pub fn retry_limit() -> u32 { 3 }`
   - `client.py`: `limit = retry_limit()`
3. For the local model, install llama-server and any instruction model. Keep
   it stopped until step 2.1, then run
   `llama-server -m <model.gguf> --port 8080`.
4. Have an OpenRouter API key with a small credit limit. Enter it only into
   Turing, never into chat, files, or commits.
5. Open the test folder in Turing and click **Turing AI** (sparkles) in the
   activity rail.

## 1. Availability and keys (AI-007, MODEL-006)

1. With llama-server stopped, the model picker shows **Auto (local first)**
   and the status line says no local server is ready on 127.0.0.1:8080.
2. Select **llama.cpp**. The option reads **(local · offline)** and the status
   line reads "No local server is running on 127.0.0.1:8080."
3. Select **Qwen3-Coder via OpenRouter**. Expand **OpenRouter API key**, save
   the key, and confirm the card collapses to **OpenRouter API key saved**.
4. On macOS, open Keychain Access and confirm an entry for service
   `dev.turingcore.ide`, account `ask-openrouter`. Confirm the key appears
   nowhere in the test folder.

## 2. Local and cloud answers (AI-001, AI-005, AI-006)

1. Start llama-server and wait until `curl 127.0.0.1:8080/health` returns 200.
   Focus the model picker; **(local · offline)** disappears.
2. With **llama.cpp**, ask "Where is retry_limit defined?". The answer streams,
   cites `limits.rs` first, and reads **Answered by llama.cpp (local)**.
3. Ask a long question and press **Stop** while it streams. The status line
   reads "Response stopped." and no further text arrives.
4. With **Qwen3-Coder via OpenRouter**, ask the same question. A native dialog
   lists the question and every shared file range, and the panel shows the
   same ranges as chips. Choose **Cancel**: nothing is sent,
   and the question returns to the composer.
5. Ask again and choose **Send once**. The answer reads **Answered by
   Qwen3-Coder via OpenRouter (cloud)** and shows input and output token
   counts. The dialog says providers that store or train on request data are
   excluded.
6. Optional, with Ollama: expand **Local server**, enter `127.0.0.1:11434`
   and an installed model name, and click **Save local server**. With
   **llama.cpp** selected and llama-server stopped, the local answer comes
   from Ollama. Entering `example.com:11434` shows a loopback-only error and
   saves nothing.
7. Budgets (OPT-004, OPT-005, OPT-006): with **Qwen3-Coder via OpenRouter**,
   expand **Cloud budget**. Entering `0` or `1.5` shows an error. Save `1`.
   The sharing dialog and panel show "≈N input tokens (estimate)"; after **Send
   once**, the card reads "Today: X of 1 tokens (measured)" with X equal to the
   answer's input plus output tokens. Ask again: an inline "Today's cloud budget
   is used" prompt appears with focus on **Send anyway**. **Cancel** keeps the
   question; **Send anyway** opens the sharing dialog. With **llama.cpp**, no
   prompt appears.

## 3. Auto routing (MODEL-003, MODEL-004, MODEL-005)

1. Select **Auto (local first)** with llama-server running. Ask a question.
   No sharing dialog appears and the answer is labeled local.
2. Stop llama-server. Ask again. The status line notes that Auto will ask
   before using the cloud, the sharing dialog appears, and after **Send once**
   the answer is labeled cloud. **Cancel** sends nothing.

## 4. Index and traceable context (CTX-001, CTX-005, CTX-006, CTX-007)

1. Expand **Workspace index**. It reports **Ready** and a file count.
2. In a terminal, add a file containing `fn retry_backoff() {}`. Within a few
   seconds the file count increases. Ask "What is retry_backoff?" and confirm
   the new file is cited.
3. **Pause**, **Resume**, **Rebuild**, and **Disable** each update the status.
   Ask still answers while the index is paused or disabled.
4. Click a source chip. The editor opens that file at the cited line. Edit and
   save the file, then click the chip again: Turing reports that the file
   differs from the cited version.
5. Create `secret.rs` and `.env` containing `retry_limit`. Neither is ever
   cited.
6. Select lines 1–3 of a saved file, right-click, and choose **Ask Turing AI
   About Selection**. The Turing AI panel opens with a chip such as
   `src/a.rs:1–3` and the composer focused. Ask "What does this do?": the
   answer cites the selection as [1] and the chip clears. With the cloud model,
   the consent dialog lists the selected range. Remove a chip with its **×**
   button. Type in the file without saving: the **Selection** menu item is
   disabled with "Save the file to ask about a selection." Attach a selection,
   then change and save the file before asking: Ask reports that the file
   changed and asks you to select the lines again.

## 5. Preferences, history, and feedback (AI-008, EVO-001, EVO-002)

1. Choose a model, then reopen the folder without saving anything: the model
   persists. Expand **Project preferences and history**, enter a convention,
   and click **Save conventions**. Reopen the folder: the convention persists. A cloud sharing dialog includes the
   convention.
2. Leave **Keep the last 20 completed answers** off and reopen the folder. The
   conversation is empty.
3. Turn retention on, ask a question, rate it **Helpful**, and reopen the
   folder. The answer and rating return. Click **Clear conversation**, then
   turn retention off. Reopening shows an empty conversation.

## 6. Autocomplete foundation (AI-004, EDT-004)

1. With a managed language server approved, type in a supported file. The
   completion list offers server suggestions for the current revision.

## 7. Accessibility and failure handling

1. Operate the panel with the keyboard only. Tab reaches the composer, model
   picker, send button, source chips, and feedback buttons. Enter sends and
   Shift+Enter adds a line.
2. With VoiceOver, NVDA, or Orca running, the status line announces generating,
   ready, stopped, and errors.
3. Revoke the OpenRouter key on the provider website and ask with the cloud
   model. Turing reports that OpenRouter rejected the key, and the IDE keeps
   working.
