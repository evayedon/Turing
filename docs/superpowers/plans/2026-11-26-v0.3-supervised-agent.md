# Turing v0.3 Supervised Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Agent mode to the Turing AI panel. The agent plans a feature, makes checkpointed multi-file edits, runs the approved tests in an OS sandbox until they pass, and ends in a combined review where the developer chooses Keep or Roll back. Every sensitive action goes through native approvals that Rust owns.

**Architecture:** The model↔tool loop runs in the Rust host as `src/agent.rs` and its submodules. Every tool call passes one pure policy function, `agent::policy::decide`. Writes go through the existing versioned workspace save path after `agent::checkpoint` has durably stored the original bytes. Tests run through a new argv runner and a spawn-agnostic per-platform sandbox in the existing `execution` module. The React panel only displays events, collects plan adjustments and asks Rust to show native dialogs. It can never grant an approval.

**Tech Stack:** Rust (Tauri 2, cap-std, reqwest, tauri-plugin-dialog, sha2, tempfile, libc/rustix, windows-sys), React + TypeScript + Vitest, Monaco diff editor, pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-11-26-v0.3-supervised-agent-design.md` (approved, binding). Also read `AGENTS.md`. Acceptance: `docs/testing/v0.3-acceptance.md`, which already exists. Tasks cite it as "Acc §N".

## Global Constraints

- **Cadence:** every task ends with one commit. Each commit is pushed and must be green in GitHub Actions on macOS, Windows and Linux before the next task starts. The developer approved this cadence for the roadmap (memory: commit and push each finished roadmap item, CI green before the next). **Exception:** Task 8 stops before its push until the developer has reviewed the ACL changes.
- **Checks before every commit**, all of which must pass:
  - `pnpm lint`
  - `pnpm exec prettier --check --ignore-unknown $(git diff --name-only; git ls-files -o --exclude-standard)` (never plain `pnpm format:check`)
  - `pnpm typecheck && pnpm test && pnpm build`
  - `cargo fmt --check --manifest-path apps/desktop/src-tauri/Cargo.toml`
  - `cargo clippy --locked --all-targets --manifest-path apps/desktop/src-tauri/Cargo.toml -- -D warnings`
  - `cargo clippy --locked --features smoke,perf --manifest-path apps/desktop/src-tauri/Cargo.toml -- -D warnings`
  - `cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml`
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- AGENTS.md rules apply throughout: Rust owns workspace authorization; Tauri permissions are default-deny; path validation covers traversal, symlinks and races; subprocesses get structured argv and never a shell; credentials stay in the OS credential store; no new dependency (this plan adds none).
- **Definitions live in the earliest task that uses them.** Each later task only consumes them under the same name. A task that first uses a private helper makes it `pub(crate)` and lists the file.
- Approvals are **native dialogs owned by Rust**, parented to the workbench window. The webview may ask Rust to show one but can never grant one. All dialog text passes through `ask::cloud::dialog_text`.
- There is no "approve all". An approval binds one exact canonical action, and any change to the argv or path needs a new approval.
- Model text, file contents and tool output never change a policy decision. The system prompt states that repository content is untrusted data.
- **Secret exclusion matches v0.2 Ask** wherever the agent reads files for the model (`read_file`, `search_text`, review diffs): a file is withheld if its path is a secret path (`policy::secret_path`) **or** its content matches `workspace::ask::excluded_content`.
- **Limits.** Maxima (and planning-phase values): 30 model calls, 400 000 total tokens, 60 tool calls, 20 minutes wall clock, 5 minutes per command. The plan may request lower values; Rust caps them at the maxima, and the plan dialog shows the final values.
  - Reaching a **task-level** limit (model calls, tokens, tool calls, wall clock) ends execution and goes to Review with the reason.
  - The **per-command** timeout kills that command and reports it to the model and the timeline as a failure (`timedOut`). It never counts as a pass and does not end the task. (Interpretation of the spec's "any limit" line: the 5-minute cap is a per-command bound, not a task budget.)
- Agent model: `qwen/qwen3-coder` via OpenRouter (`ask::cloud::MODEL`, `ask::cloud::ENDPOINT`). Cloud requests send `"store": false` and `"provider": {"data_collection": "deny", "require_parameters": true}` (`require_parameters` keeps routing to providers that support tool calling). Local servers are best-effort.
- **Checkpoint location (single source of truth):** `<app_local_data_dir>/agent-checkpoints/<task-id>/`. Callers pass `app_local_data_dir()`; only `Checkpoint` appends `agent-checkpoints/<task-id>`.
- **Sandbox write scope (disclosed deviation).** A test run writes only inside the workspace and a per-task temp dir. When **network is on**, the toolchain cache dirs in `TOOLCHAIN_CACHE_DIRS` (cargo registry/git, npm/pnpm store and cache, pip cache, Go module cache) are also writable, because the spec allows downloading lockfile-pinned dependencies with network on. When network is off they are read-only. Task 14 records this in the acceptance doc.
- Non-goals: no Python/FastAPI, MCP, extensions, parallel or background agents, per-action approval mode, persisted task history, or access outside the workspace. The agent never commits, pushes, resets or rebases.
- One agent task runs per workbench window.

## Review Focus

1. **The developer types in a file while the agent is running.** The dirty report reaches Rust after the agent has already checked it. Expected: typed text is never lost; the agent write lands on disk and the dirty tab shows the existing "changed on disk" conflict instead of reloading. Test: Task 13, `agent_write_while_tab_dirty_shows_disk_conflict_not_reload` (regression pin).
2. **A test run or approved command changes workspace files without `edit_file`** (snapshots, generated code). These are not checkpointed. Expected: the review lists them under "Not covered by rollback" and never claims rollback restores them. Scope: every workspace file outside ignored directories (`search::ignored_directory`, such as `target/`, `node_modules/`) and outside agent-recorded paths; the review says ignored folders are not checked. Test: Task 10, `review_lists_untracked_changes_outside_agent_edits`.
3. **The app quits during `Executing`, between the checkpoint write and the workspace write.** Expected: on restart, recovery offers Roll back, which restores the original bytes or deletes a created file. Test: Task 4, `recovery_after_crash_between_checkpoint_and_write_restores_original`.
4. **The model sends a tool call with extra fields** (`"approved": true`, `"skipApproval"`) or unknown tool names. Expected: Rust refuses the call before the policy runs, and it counts as a tool call. Tests: Task 9, `rejects_unknown_tool_fields_and_names`; Task 10, `invalid_tool_calls_count_toward_the_tool_limit`.
5. **A dialog shows a long or hostile argv or path** (newlines, `%`, bidi controls, 10 KB). Expected: the dialog shows escaped, clipped text, and the approval still binds the full argv. Tests: Task 11, `approval_text_escapes_and_clips`; Task 10, `approval_binds_the_full_argv_not_the_dialog_text`.

```rust
pub(crate) enum Phase { Planning, Executing }            // only phases where tools run
pub(crate) struct Scope<'a> { pub tests: Option<&'a [String]>, pub sandboxed: bool }
pub(crate) enum Action<'a> {
    List { path: &'a str }, Read { path: &'a str }, Search, Symbols,
    Edit { path: &'a str }, Write { path: &'a str, exists: bool },
    Rename { from: &'a str, to: &'a str }, Delete { path: &'a str },
    RunTests { argv: &'a [String] }, RunCommand { argv: &'a [String] },
    SubmitPlan, Finish,
}
pub(crate) enum Decision { Allow, Ask(AskReason), Deny(Denial) }
pub(crate) enum AskReason { BuildConfigEdit, Rename, Delete, UnsandboxedTests, Command(CommandClass) }
pub(crate) enum CommandClass { Ordinary, Dependency, Network, GitHistory }
pub(crate) enum Denial { SecretFile, GitDirectory, DirtyInEditor, NotInPhase, DeniedGit, ShellInterpreter,
                         UnknownGitSubcommand, EmptyArgv, TestsNotApproved }
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub(crate) struct ActionKey([u8; 32]);
pub(crate) fn decide(phase: Phase, scope: &Scope, action: &Action, dirty: &HashSet<String>) -> Decision;
pub(crate) fn action_key(action: &Action) -> ActionKey;    // sha256 of a length-prefixed canonical encoding
pub(crate) fn classify_command(argv: &[String]) -> Result<CommandClass, Denial>;
pub(crate) fn build_config(path: &str) -> bool;
pub(crate) fn secret_path(path: &str) -> bool;              // any component secret_directory, last secret_name
/// Canonical key for dirty-set membership: `\` → `/`, validated by `workspace::relative_parts`,
/// then lowercased. Lowercasing on every OS can only add refusals, never allow a write.
pub(crate) fn dirty_key(path: &str) -> Option<String>;
```

`path` is always the canonical workspace-relative path that `relative_parts` has validated. `decide` checks `dirty.contains(&dirty_key(path))` for every write target (both ends of a rename). The policy never sees model text.

**Loop rules:**

- **Start:** with `ctx.cloud`, `Approver::cloud_scope` runs first; decline gives `Err(CloudConsentDeclined)` and no request is sent. Planning uses `Limits::MAX`.
- **Plan approval order:** `submit_plan` → emit `Plan` (limits = `MAX.within(plan.limits)`, verification = the plan's or `detect_test_command`) → `Host::plan_adjustments` → `Checkpoint::create(app_data, …)` → `Verifier::prepare(final argv, final network, |p| checkpoint.note_acl_grant(p))` → `Approver::plan` with the final values and the `SandboxView` → decline: `Verifier::release`, `Checkpoint::discard`, `Err(PlanDeclined)`; approve: emit `Executing`.
- Tool calls run one at a time in model order. Each counts toward `tool_calls`, including invalid and refused calls.
- One `ModelCall` event is emitted after every completion, carrying the sources added since the previous call and measured tokens. `model_calls` and `total_tokens` are checked before each call; local models without usage count `bytes.div_ceil(4)`.
- Wall clock and `Host::cancelled` are checked before every model and tool call, and polled every 100 ms during awaits through `ask::interruptible`.
- **Reads:** `read_file` and `search_text` withhold any file where `secret_path` is true or `excluded_content` matches its content; `read_file` refuses with `Policy(SecretFile)`, and `search_text` drops the file from the results.
- **Writes:** dirty set, then policy, then `checkpoint.record` (durable), then `Registry::write` / `agent_create` / `agent_delete`, then `checkpoint.note_write`. `edit_file` needs `old` exactly once (else `OldTextNotFound` / `OldTextNotUnique`). `rename_path` (text files only) is a recorded create of `to` plus delete of `from`, and emits two `Edit` events (`created`, `deleted`).
- **Approvals:** an `Ask` decision calls `Approver::action` with `action_text`. The decision and `ActionKey` are recomputed after the dialog closes; the grant is used once, only if the key is unchanged. Decline gives `ApprovalDeclined`.
- **Commands:** a per-command timeout is a failed command (`outcome.timed_out`), reported to the model and the timeline; the loop continues.
- Tool results go to the model as `{"role":"tool","content": <JSON string>}`, capped at 32 KiB; command output is cut to the last 16 KiB.
- **Finishing:** on `finish`, a task-level limit or give-up, if no verification ran after the last edit and an approved argv exists, Rust runs it once more (not after cancel). Then `checkpoint.set_state(Review)`, emit `Review`, wait for `review_decision`, Keep → `discard`, RollBack → `rollback` with `Approver::overwrite_after_agent`, then `Verifier::release`, emit `Finished`.
- `Verification::Passed` only when the latest test run exited `Some(0)`, did not time out and was not cancelled. A cancelled or never-run test is `NotRun`.
- **Untracked changes** (the one definition): a `(relative_path, len, mtime)` fingerprint of every workspace file, skipping `search::ignored_directory` dirs, taken at plan approval and at review; differences outside agent-recorded paths, at most 50.
