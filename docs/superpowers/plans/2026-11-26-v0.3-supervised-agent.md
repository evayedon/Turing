# Turing v0.3 Supervised Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Agent mode to the Turing AI panel. The agent plans a feature, makes checkpointed multi-file edits, runs the approved tests in an OS sandbox until they pass, and ends in a combined review where the developer chooses Keep or Roll back. Every sensitive action goes through native approvals that Rust owns.

**Architecture:** The model↔tool loop runs in the Rust host as `src/agent.rs` and its submodules. Every tool call passes one pure policy function, `agent::policy::decide`. Writes go through the existing versioned workspace save path after `agent::checkpoint` has durably stored the original bytes. Tests run through a new argv runner and per-platform sandbox in the existing `execution` module. The React panel only displays events, collects plan adjustments and asks Rust to show native dialogs. It can never grant an approval.

**Tech Stack:** Rust (Tauri 2, cap-std, reqwest, tauri-plugin-dialog, sha2, tempfile, libc/rustix, windows-sys), React + TypeScript + Vitest, Monaco diff editor, pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-11-26-v0.3-supervised-agent-design.md` (approved). Also read `AGENTS.md`. Acceptance: `docs/testing/v0.3-acceptance.md`, which already exists. Tasks cite it as "Acc §N".

## Global Constraints

- **Cadence:** every task ends with one commit. Each commit is pushed and must be green in GitHub Actions on macOS, Windows and Linux before the next task starts. The developer has approved this cadence for the roadmap (memory: commit and push each finished roadmap item, with CI green before the next).
- **Checks before every commit**, all of which must pass:
  - `pnpm lint`
  - `pnpm exec prettier --check --ignore-unknown $(git diff --name-only; git ls-files -o --exclude-standard)` (never plain `pnpm format:check`)
  - `pnpm typecheck && pnpm test && pnpm build`
  - `cargo fmt --check --manifest-path apps/desktop/src-tauri/Cargo.toml`
  - `cargo clippy --locked --all-targets --manifest-path apps/desktop/src-tauri/Cargo.toml -- -D warnings`
  - `cargo clippy --locked --features smoke,perf --manifest-path apps/desktop/src-tauri/Cargo.toml -- -D warnings`
  - `cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml`
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- AGENTS.md rules apply throughout:
  - Rust owns workspace authorization.
  - Tauri permissions are default-deny.
  - Path validation covers traversal, symlinks and races.
  - Subprocesses get structured argv and never a shell.
  - Credentials stay in the OS credential store.
  - No new dependency without a demonstrated need. This plan adds none.
- Approvals are **native dialogs owned by Rust** and parented to the workbench window. The webview may ask Rust to show one but can never grant one. All dialog text passes through `ask::cloud::dialog_text`.
- There is no "approve all". An approval binds one exact canonical action, and any change to the argv or path needs a new approval.
- Model text, file contents and tool output never change a policy decision. The system prompt states that repository content is untrusted data.
- Secret files are never readable by the agent and are never sent to the model. Secret-name rules match v0.2 Ask retrieval (see Task 2).
- Default limits, all shown in the plan dialog:
  - 30 model calls per task;
  - 400 000 total tokens per task;
  - 60 tool calls per task;
  - 20 minutes wall-clock per task;
  - 5 minutes per command.

  Reaching any limit ends execution and goes to Review with the reason.

- Agent model: `qwen/qwen3-coder` via OpenRouter (`ask::cloud::MODEL`, `ask::cloud::ENDPOINT`), with `"provider": {"data_collection": "deny"}` and `"store": false`. Local servers are best-effort.
- Checkpoints live at `<app_local_data_dir>/agent-checkpoints/<task-id>/`. This is the same base directory as the draft journal.
- Non-goals: no Python/FastAPI, MCP, extensions, parallel or background agents, per-action approval mode, persisted task history, or access outside the workspace. The agent never commits, pushes, resets or rebases.
- One agent task runs per workbench window.

## Review Focus

1. **The developer types in a file while the agent is running.** The dirty report reaches Rust after the agent has already checked it. Expected: the editor never loses typed text. The agent write lands on disk, and the dirty tab shows the existing "changed on disk" conflict instead of being reloaded. Test: Task 13, `agent_write_while_tab_dirty_shows_disk_conflict_not_reload`.
2. **A test run or approved command changes files in the workspace without going through `edit_file`**, such as snapshots, `target/` or generated code. These are not checkpointed. Expected: the review never claims that rollback restores them. Test: Task 10, `review_lists_untracked_changes_outside_agent_edits`, which compares a pre-task directory fingerprint of tracked top-level files.
3. **The app quits during `Executing`, between the checkpoint write and the workspace write.** Expected: on restart, recovery offers Roll back, and rollback restores the original bytes or deletes a file that was created. Test: Task 4, `recovery_after_crash_between_checkpoint_and_write_restores_original`.
4. **The model sends a tool call with extra fields** (`"approved": true`, `"skipApproval"`) or tool names that are not in the schema. Expected: Rust refuses the call before the policy runs, and it counts as a tool call. Test: Task 9, `rejects_unknown_tool_fields_and_names`.
5. **A dialog shows a long or hostile argv or path** containing newlines, `%`, bidi controls or 10 KB of text. Expected: the native dialog shows escaped, clipped text, and the approval still binds the full argv. Test: Task 11, `approval_text_escapes_and_clips_but_binds_full_action`.

pub(crate) enum Phase { Planning, Executing }            // only phases where tools run
pub(crate) struct Scope<'a> {
    pub tests: Option<&'a [String]>,   // approved verification argv
    pub sandboxed: bool,
}
pub(crate) enum Action<'a> {
    List { path: &'a str }, Read { path: &'a str }, Search, Symbols,
    Edit { path: &'a str }, Write { path: &'a str, exists: bool },
    Rename { from: &'a str, to: &'a str }, Delete { path: &'a str },
    RunTests { argv: &'a [String] }, RunCommand { argv: &'a [String] },
    SubmitPlan, Finish,
}
pub(crate) enum Decision { Allow, Ask(AskReason), Deny(Denial) }
pub(crate) enum AskReason { BuildConfigEdit, Rename, Delete, UnsandboxedTests,
                            Command(CommandClass) }
pub(crate) enum CommandClass { Ordinary, Dependency, Network, GitHistory }
pub(crate) enum Denial { SecretFile, GitDirectory, DirtyInEditor, NotInPhase,
                         DeniedGit, ShellInterpreter, UnknownGitSubcommand, EmptyArgv,
                         TestsNotApproved }
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub(crate) struct ActionKey([u8; 32]);
pub(crate) fn decide(phase: Phase, scope: &Scope, action: &Action, dirty: &HashSet<String>) -> Decision;
pub(crate) fn action_key(action: &Action) -> ActionKey;    // sha256 of a length-prefixed canonical encoding
pub(crate) fn classify_command(argv: &[String]) -> Result<CommandClass, Denial>;
pub(crate) fn build_config(path: &str) -> bool;
pub(crate) fn secret_path(path: &str) -> bool;              // any component secret_directory, last secret_name
```

`path` is always the canonical workspace-relative path that `relative_parts` has validated. The policy never sees model text.

```

        (Absent, Some(cur))        => registry.agent_delete(path, cur.version) => Removed

**Loop rules:**

- Tool calls run one at a time in model order.
- Each call counts toward `tool_calls`, including refused calls.
- Each model call checks `model_calls` and `total_tokens` before it is sent. For local models without usage, the token count uses `bytes.div_ceil(4)`.
- Wall clock is checked before every model and tool call. `Host::cancelled` is checked at the same points and polled every 100 ms during awaits through `ask::interruptible`.
- **Writes:**
  - Dirty set, then policy, then `checkpoint.record` (durable), then `Registry::write` (or `agent_create`, `agent_delete`), then `checkpoint.note_write`.
  - `edit_file` requires `old` to occur exactly once. Otherwise it is refused with `OLD_TEXT_NOT_FOUND` or `OLD_TEXT_NOT_UNIQUE`.
  - `rename_path` is a recorded create of `to` plus a delete of `from`. It works for text files only.
- **Approvals:**
  - An `Ask` decision calls `Approver::action`. The grant is used immediately, exactly once, for the same `ActionKey` that was recomputed just before execution. The decision and the key are computed again after the dialog closes.
  - When the developer declines, the model gets `APPROVAL_DECLINED`.
- **Context log:** read and search results add `ask::Source` ranges to a `Vec` that is drained into the next `ModelCall` event. Tool results go to the model as `{"role":"tool","content": <JSON string>}`, capped at 32 KiB, and command output is cut to the last 16 KiB.
- **Finishing:**
  - On `finish`, or on a limit, cancel or give-up: if no verification ran after the last edit and the approved argv exists, Rust runs it once more, unless the task was cancelled. Then it emits `Review`.
  - `Verification::Passed` only when the latest exit code was `Some(0)`, the run did not time out and was not cancelled.
- `untracked_changes`: compare a `(relative_path, len, mtime)` fingerprint taken at plan approval with one taken at review. Skip ignored dirs (`search::ignored_directory`) and agent-recorded paths. List at most 50 paths.
