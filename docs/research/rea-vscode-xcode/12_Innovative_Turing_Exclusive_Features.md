# Turing differentiation candidates

These are proposals. Comparative advantage is a hypothesis until tested against current versions and equivalent tasks.

| Candidate                                  | Why it might help and evidence base                                                                                                                                                                                          | Implementation prerequisites                                               | Verification criterion                                                                                       |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Diagnostic-to-verification timeline        | Combine Xcode's report discipline with provider-oriented diagnostics to follow one issue from editor to build/test and fix review. [Workflows](06_UI_UX_and_Developer_Workflows.md)                                          | Problems, run IDs, document revisions and artifact retention.              | Given two similar failures, reproduce and distinguish each by exact input, configuration and resulting test. |
| Human-readable agent capability receipts   | Make user approvals inspectable and narrowly replayable with the operation, workspace generation, paths, redaction policy and outcome. Build on native Turing grants. [Security](07_Performance_Security_and_Reliability.md) | Policy broker, immutable operation log and permission UI.                  | Threat fixtures cannot reuse stale approval or submit shell input; a user can identify what changed and why. |
| Context disclosure and local-first routing | Show source ranges and revisions selected for a model before external transfer. Keep local/no-network workflows first-class. [Architecture](10_Turing_Next_Generation_Architecture.md)                                       | Context manifests, secret filters, model broker and per-provider consent.  | Privacy test corpus stays local, prompts are cancellable and context is replayable from permitted snapshots. |
| Reviewable, verified change bundles        | Bind proposed file operations, targeted tests and resulting evidence to one reviewable patch with rollback.                                                                                                                  | Workspace edits, conflict/version checks, tool scheduler and test history. | Concurrent change, failed test and interrupted rollback produce recoverable, understandable states.          |
| Cross-tool configuration explanation       | Show which compiler flags, SDK, target, runtime and source revision affected completion, build and debug in one place. Draws on Xcode schemes and LSP context. [Editor](04_Editor_and_Language_Intelligence.md)              | Project adapters, diagnostics provenance, launch plans.                    | Resolve incorrect completion caused by a configuration change without manually inspecting tool logs.         |
| Resource-aware workspace modes             | Offer responsive editing in large workspaces by trading optional indexing depth and AI context size against an explicit resource budget. [Performance](07_Performance_Security_and_Reliability.md)                           | Telemetry, interruptible indexes, workload estimates.                      | Keep agreed p95 input latency while changing budgets without losing save correctness.                        |

Evaluate these with user workflows and named reference baselines before calling them exclusive. Keep AI and context indexing optional so core IDE functions remain available offline.
