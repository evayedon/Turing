Existing recovery limits include metadata that may not survive atomic replacement and detached descendants that may outlive some sessions. Treat them as explicit operating-system boundaries. Source size and bounded scanning are measurable leads; no hotspot was established by profiling. Benchmark renderer scheduling, save-copy cost, search and terminal throughput before optimizing.

## Verification priorities from current wiring

- Per-window resource maps constrain native authority, while workbench text and layout preferences use frontend state. Test opening a second workbench during error recovery, terminal-only capability denial, and app termination with dirty editors. UI tests that stub IPC cannot establish native window authorization.
- Save publication handles races and preserves draft state. Unix and Windows use different replacement primitives. Simulate competing writers, filesystem metadata constraints and OS-specific publication failure before broadening batch-edit operations.
- Workspace search ignores fixed directories and excludes unsaved edits. The future index should reconcile watcher events with disk and distinguish dirty buffers in results. Measure time to first result and cancellation latency, including slow filesystems.
- The CI workflow builds on Ubuntu 24.04, macOS 15 and Windows 2025 with a 4 GiB Node heap option and locked Rust tests. This is source evidence of CI configuration. Native GUI launch and real workload latency need separate verification. [Workflow](../../../.github/workflows/ci.yml)
