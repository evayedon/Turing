# Proposed Turing architecture

## Ownership and identities

1. **Workbench.** Keep React, Monaco and Nebula. Feature modules contribute typed commands, views and settings to a per-window composition root. Define activation and disposal points. Use the same command handler and availability predicate across all invokers.
2. **Documents.** Distinguish opaque Document ID, workspace-scoped canonical URI, buffer version, disk version and View ID. Native grants stay server-owned. View state is local; a buffer is shared by views. Version snapshots, preview edits, and preserve Monaco undo.
3. **Native tooling.** Per-window services own tickets; a shared spawn/teardown layer owns environment policy, handles, output bounds, quotas and cancellation. Policy inputs include caller class, grant generation, executable provenance, desired capability and operation-specific approval. Do not collapse user shell, tools and agent access into one IPC surface.
4. **Project and operations.** Project adapters discover targets/configurations without auto-executing repository scripts. Scheduler tracks graph edges, run identity, inputs, outcome and artifacts. Keep Cargo, CMake, npm and Swift build semantics in their tools. Normalize compiler/test results into source-linked reports. Gate builds, debug launches, test runs, previews and deployment separately.
5. **Language and debug.** Run managed stdio transports with framing limits, negotiated capabilities, bounded concurrency and protocol state machines. Diagnostic key is producer × document URI × content revision or run ID. Parse server edits into separately authorized proposals. DAP tracks adapter event sequence, verified breakpoints and lifecycle; adapter reverse requests require policy.
6. **Source control and persistence.** Read-only Git operations first, then previewed mutations with credential integration through OS stores. Use versioned, scoped local preferences and an independently migrated store for recovery, indexes and run history. Never restore a process grant from persisted metadata.
7. **Extensions and native integration.** Declarative themes, snippets and commands first. Any future executable plugin requires an authorization manifest, provenance, independent process containment, versioned API, CPU/RSS budgets and revocation. Monaco does not supply VS Code API compatibility. Use native pickers, keychains and platform adapters; support provider locality before introducing authenticated remote sessions.
8. **Model and agent runtime.** Broker cloud/local models behind streamed, cancellable contracts. Provider credentials stay out of renderer and model prompts. Use versioned context manifests, source references and network policy. Agent state is plan → preview → scoped approval → execute → verify → review. Approval binds tool, parameters, workspace generation and expiry. A dedicated principal cannot inherit human PTY or debugger rights.
9. **Previews, generation and deploy.** Generate into reviewed patches or checkpointed scratch trees. Isolate preview runtimes by project and allow only explicit network/device connections. Deployment adapters consume immutable artifact IDs, destination-scoped credentials and explicit release approval; Apple deployment requires supported Apple tools.
10. **Observability.** Instrument startup readiness, IPC queuing, file scans, model memory, tool latency, cancellation and cleanup with opt-in, redacted diagnostics. Use native smoke tests per OS, contract fixtures between TypeScript and Rust, and reproducible scenarios to compare performance.

## Boundary tests and decisions

| Decision                                                    | Motivation/evidence                                                                                    | Release proof                                                                                                                                                       |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep project knowledge separate from authority              | Existing Turing grant model and Xcode target contexts [audit](08_Turing_Current_Architecture_Audit.md) | Replacing a workspace revokes queued LSP/build/agent activity without confusing a same-named module.                                                                |
| Prefer a single native broker with distinct launch policies | PTY and Run already own independent services [processes](05_Terminal_Debugging_and_Build_Systems.md)   | Malformed, stalled or compromised adapters cannot open arbitrary files or start through a different tool principal. OS process containment documented per platform. |
| Index cautiously and asynchronously                         | Build-aware SourceKit-LSP and versioned LSP [editor](04_Editor_and_Language_Intelligence.md)           | Reconcile overflow, mark stale results, and bound CPU/memory with concurrent editing.                                                                               |
| Keep reports structured and context reproducible            | Xcode reports and VS Code provider design [workflows](06_UI_UX_and_Developer_Workflows.md)             | A failed test links to a saved revision, tool/configuration and reproducible input set.                                                                             |

Confidence is high in protocol feasibility and local source boundaries. Production resource costs, host isolation mechanisms and model quality need prototypes and acceptance gates.
