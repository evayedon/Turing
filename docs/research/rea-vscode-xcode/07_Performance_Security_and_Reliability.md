# Performance, security and reliability

| Finding                                                                                                                                                          | Confidence and evidence                                                                                                                                                               | Acceptance gate                                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VS Code documents diagnosing startup, renderer, extension host and remote performance separately.                                                                | High. [Performance troubleshooting](https://github.com/microsoft/vscode/wiki/Performance-Issues)                                                                                      | Collect process-level CPU/RSS, cold and warm startup, time to editable buffer, search cancellation and first diagnostics. Record binary version, OS, hardware, repository and sample size.                        |
| Xcode exposes build timing and incremental build tuning; Instruments provides runtime profiling.                                                                 | High. [Build tuning](https://developer.apple.com/documentation/xcode/improving-the-speed-of-incremental-builds), [Instruments](https://developer.apple.com/documentation/instruments) | Time clean and incremental builds independently; attribute the critical path and verify no-op builds. No cross-product speed ranking is justified by this study.                                                  |
| Workspace Trust can restrict VS Code automation in unfamiliar projects, while extension and remote permissions remain separate attack surfaces.                  | High. [Workspace Trust](https://code.visualstudio.com/docs/editing/workspaces/workspace-trust), [Extension host](https://code.visualstudio.com/api/advanced-topics/extension-host)    | Keep grants for viewing, tool execution, external network and agent writes separate. Test workspace change while launch is queued, path replacements and renderer restart.                                        |
| Tool output and repository instructions can cross human, plugin and model contexts. PTYs and compilers execute at OS-user privilege unless separately sandboxed. | High for Turing launch model, design inference for future risks. [Turing native scope](../../architecture.md)                                                                         | Bound subprocess CPU/memory/output where supported; redact sensitive environment values; treat tool metadata as untrusted. Test overflow, teardown, cancellation, child escape limitations and audit log privacy. |

Proposed measurement suite: 20 cold and 30 warm launches per platform; p50 and p95 on 1k, 10k and 50k synthetic files; editor latency during search/index load; terminal throughput and dropped/truncated-byte accounting; helpfully classified out-of-resource errors; memory after repeated reopen and shutdown. Set thresholds after the baseline. Track Linux/macOS PTY and Windows ConPTY independently. Record WebView versions and separate build-host memory from runtime measurements.
