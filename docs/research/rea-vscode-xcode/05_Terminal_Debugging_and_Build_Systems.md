Turing currently snapshots the active saved Python/C++ file and runs it with bounded output. Keep this path for single files. Project builds require workspace trust and direct tool execution within an authorized context. Attach debugging needs separately selected process authority. Use structured arguments and fixed adapter provenance throughout.

## Verification scenarios

- **Terminal ownership.** Start two sessions and switch layout while producing output. Close one tab, then its entire window. Ensure only its PTYs and queues close. Record process-tree assumptions under Unix groups and Windows Job Objects separately.
- **Terminal metadata.** Strip unsafe default link schemes, check pasted multiline input through the terminal's paste mode, and label command markers and cwd claims as shell-provided. Render command navigation without feeding shell-provided strings back into privileged commands.
- **Build outputs.** Compare cold, no-op and changed-header builds in one fixture. Preserve explicit flags and normalized paths and show which tool produced a diagnostic. Keep truncated output warnings while retaining terminal-compatible logs.
- **Debugger lifecycle.** A debuggee hits a verified source breakpoint, steps, updates location and exits. Repeat with crash, startup failure, stale source mapping, adapter timeout and cancelled launch. Attach remains a separate later surface until its authorization and detach behavior are proven.
