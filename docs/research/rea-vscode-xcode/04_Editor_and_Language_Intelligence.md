# Editor and language intelligence

| Finding                                                                                                                                                                                                                       | Evidence and confidence                                                                                                                                                                                                                | Turing implication and verification                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A shared model can back several editor views while selection and scroll remain view-local. Monaco text models cover edit operations, decorations and undo integration.                                                        | High. [Text model source](https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/model/textModel.ts), [editor integration](https://github.com/microsoft/vscode/tree/main/src/vs/workbench/services/editor)                 | Separate Document URI, buffer/version, saved snapshot and editor-view identity. Split a dirty document and verify both views see edits with independent selection and shared undo.                                           |
| Piece-tree buffers and bounded large-file feature policies help keep editing responsive. Diff and merge require independent models and conflict state.                                                                        | High for public source. [Piece tree](https://github.com/microsoft/vscode/tree/main/src/vs/editor/common/model/pieceTreeTextBuffer), [merge editor](https://github.com/microsoft/vscode/tree/main/src/vs/workbench/contrib/mergeEditor) | Keep Monaco's buffer. Add low-feature large text and binary handling through explicit policies. Measure input-to-paint, model memory and cleanup with large generated files.                                                 |
| Providers supply navigation, completion, hover/signature help, formatting, symbols, refactors and rename, semantic tokens, inlay hints, code lenses and code actions. LSP supplies negotiated features and position encoding. | High. [LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/), [VS Code API](https://code.visualstudio.com/api/references/vscode-api)                                                  | Offer each feature only when available. Use versioned requests, cancel obsolete work, preserve UTF-16 conversion and map results back to authorized URI. Test emoji ranges and edits racing slow replies.                    |
| SourceKit-LSP documents build-system integration and index prerequisites for cross-module queries. Xcode surfaces indexing, navigation and Fix-its; internal index ownership is unknown.                                      | High for public tooling, medium for workflow comparison. [SourceKit-LSP](https://github.com/swiftlang/sourcekit-lsp), [Xcode docs](https://developer.apple.com/documentation/xcode)                                                    | Track configuration and index freshness. Present degraded behavior while build context is incomplete. Test stale cross-module matches after switching target or branch.                                                      |
| Compiler issues and live language diagnostics have different lifetimes. Fixes can edit multiple files or declare commands.                                                                                                    | High, protocol. [LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)                                                                                                                | Use a diagnostic store by producer, URI, version and run ID. Show related ranges, navigate from Problems, preview multi-file edits and gate commands separately. Test provider restart, close, conflicts and revoked grants. |

Start with one known server and one fixture per capability. Negotiate initialize and synchronization, then wire Problems and navigation before ranked completion or semantic token deltas. Keep Monaco's native JS/TS features where appropriate and define ownership for overlapping diagnostics. Prevent language tooling from invoking arbitrary commands through server replies. Include multi-cursor/undo, accessible suggestions and diff/merge in editor regression fixtures.
